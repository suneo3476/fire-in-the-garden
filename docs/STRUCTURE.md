# 構造化ドキュメント

## 完成した構造化データ

### ✅ 完了済み

#### 1. キャラクター定義 (`src/domain/characters.json`)
- 10人のキャラクター定義（主人公、警察、探偵、探偵助手、容疑者5人、白い花）
- 各キャラクターに固有のID、名前、役割、色を定義
- `assetKey`で立ち絵素材と紐付け

#### 2. 証拠品データ (`src/domain/evidence.json`)
- 12個の証拠品/観察ポイント
- 各証拠品に以下を定義：
  - 発見テキスト
  - 尋問時のセリフ
  - ライフへの影響（-1 = 不正解、0 = 正解）
  - 条件分岐（特定の証拠発見後に変化する証拠品）
  - 重要度フラグ

**条件分岐がある証拠品**
- 消防士の「勲章バッジ」→「蝋燭のストラップ」発見後は選択不可
- 画家見習いの「枝」「砂」→ 庭師の「カバン」調査前後で判定が変化

#### 3. フラグ管理 (`src/domain/flags.json`)
- 20個のゲームフラグ定義
- 進行フラグ（章の開始、聴取完了など）
- 推理パートの状態（残りライフ、証拠発見数）
- 証拠発見フラグ（条件分岐トリガー用）

#### 4. アセットマッピング (`src/domain/assets-mapping.json`)
- **素材ファイルとゲーム内要素の紐付け**
- 6カテゴリ：
  - キャラクター立ち絵（10種）
  - 背景（6種）
  - 証拠品画像（11種）
  - UI素材（4種）
  - BGM（4曲）
  - 効果音（4種）

**特徴**
- 素材ファイルパスを後から自由に変更可能
- 配置ステータス管理（未配置/配置済み）
- 説明文付き

#### 5. シナリオ構造（ベース）(`src/domain/scenarios/`)
- スタート画面（ランダムセリフ、出勤ボタン）
- 導入シーン（クレジット表示）
- 第1章 導入（探偵・探偵助手・警察の会話）
- 第1章 事情聴取選択画面（5人から選択、聴取済みはグレーアウト）

## 🛠️ 素材管理プレビューツール (`tools/preview.html`)

### 機能
1. **素材の可視化**
   - assets-mapping.jsonを読み込んで全素材を表示
   - カテゴリごとにタブで整理
   - 配置済み/未配置を色分け表示

2. **ドラッグ&ドロップ対応**
   - 画像ファイルをドロップエリアにドロップ
   - 即座にプレビュー表示
   - ステータスが自動的に「配置済み」に変更

3. **統計情報**
   - 総素材数
   - 配置済み素材数
   - 未配置素材数

4. **保存機能**
   - 編集した設定をJSONファイルとしてダウンロード
   - 元のファイルを上書きして反映

### 使い方
```bash
# ブラウザでファイルを開く
open tools/preview.html

# または
# プロジェクトルートでローカルサーバーを起動
python -m http.server 8000
# → http://localhost:8000/tools/preview.html
```

## 📊 データモデルの設計思想

### エンジン非依存アーキテクチャ

```
┌─────────────────────────────────┐
│  ドメインモデル層                 │  ← エンジンに依存しない
│  (JSON形式)                      │     汎用的なデータ構造
│  - characters.json               │
│  - evidence.json                 │
│  - scenarios/*.json              │
│  - flags.json                    │
│  - assets-mapping.json           │
└─────────────────────────────────┘
             ↓ 変換
┌─────────────────────────────────┐
│  アダプター層                     │  ← エンジン固有の形式に変換
│  /src/adapters/monogatari/      │
│  - converter.js                  │
│  - script.js (Monogatari形式)   │
└─────────────────────────────────┘
             ↓ 実行
┌─────────────────────────────────┐
│  エンジン実行層                   │
│  Monogatari / Ren'Py / 自作      │
└─────────────────────────────────┘
```

**メリット**
- Monogatariが要件に合わなければ他のエンジンに移行可能
- シナリオデータは汎用的な資産として保存
- 素材の差し替えが容易（マッピングファイルを編集するだけ）
- ユニットテストやシナリオ検証が可能
